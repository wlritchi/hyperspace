# Launch: implementation plan

Spec: [launch spec](../specs/2026-11-10-launch.md). Two packages, in order.
The client package needs the server package, because the client e2e tests run
the real server.

## Package 1: protocol and server

- `protocol/`: `CAP_LAUNCH`, the request and response types, and
  `validate_launch_request` (the field limits of "Launch endpoint": `prompt`
  at most 64 KiB, `workspace` absolute, `parent` a session id). `launches` in
  the heartbeat body.
- `lib/accounts.py`: the `launch` scope. It cannot be with `wake`.
- `lib/store.py`: a launch table (id, account, harness, host, fields, state,
  session, reason, request id, times). Request ids kept for 24 hours. The
  prompt deleted at `started` or `failed`. A `claimed` launch with no session
  after 10 minutes becomes `failed` with `no session reported`, and a later
  link is still accepted. The verdict `starting` comes from a heartbeat with
  `launches: true` that has not expired (as `_acts_on_wakes` does for wakes).
- `lib/app.py`: the caller endpoints (`POST`, `GET`, `DELETE`) and the
  launcher endpoints (`GET ?state=pending`, `claim`, `link`, `fail`), with the
  scope and host checks. The capability in `GET /whoami`.
- Docs: the main spec (endpoint table, scope, capability, metadata link
  `launch`) and `docs/deploy.md` (the scope).

## Package 2: client

- `api.py`: the launch calls.
- `config.py`: `launches = false`.
- `launcher.py`: `launches: true` in heartbeats when the launcher acts on
  wakes and `launches` is not off. The launch pass after `resume_held`: check
  the workspace, claim, start with `HYPERSPACE_LAUNCH` and
  `HYPERSPACE_LAUNCH_PARENT`, parse `backgrounded · <job id>`, check
  `state.json` (`sessionId`, `cwd`), save `links.launch` and `links.parent` in
  local state, link. Never start twice after a claim.
- `hooks.py` and the adapter: the SessionStart hook with `source=startup`
  saves the links of the environment marker. The sync links the launch (a
  `409` is an error in the log).
- `cli.py`: `hyperspace launch` with `--host`, `--workspace`, `--model`,
  `--effort`, `--name`, `--wait`, `--json` and `--cancel`. The parent from
  `CLAUDE_CODE_SESSION_ID`. A local launch with no launcher that acts on
  launches runs one launcher pass.
- Docs: the status spec (hook table), `docs/deploy.md` (`launches`), and
  `docs/runners.md` (start a session with `hyperspace launch`).
